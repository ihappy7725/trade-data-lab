Mirror Gap

거울 통계 차이: 같은 교역, 두 나라의 서로 다른 숫자

나라 A가 "B로 이만큼 수출했다"고 신고한 값과, 나라 B가 "A에서 이만큼 수입했다"고 신고한 값을 나란히 놓고 얼마나, 어디서, 언제부터 어긋나는지 보여 주는 웹서비스. 차이의 원인은 단정하지 않고, 알려진 설명 후보와 알 수 없는 부분을 나눠 보여 준다.

핵심 질문

대상

02왜 만드나: 배경과 문제

배경

교역 한 건에는 숫자가 두 개 생긴다. 보내는 나라의 세관은 수출로, 받는 나라의 세관은 수입으로 기록한다. 이 둘을 서로의 "거울"이라고 부른다. 이론적으로는 같아야 하지만, 실제로는 기록 기준과 경로 때문에 자주 다르다. 미국과 중국이 서로 신고한 양국 교역액이 다르다는 점은 여러 연구에서 다뤄졌고, 홍콩을 거치는 재수출이 주요 이유 중 하나로 꼽힌다.

지금의 불편

  • 뉴스와 보고서는 보통 한쪽 나라의 숫자 하나만 쓴다. 같은 "한국의 대○○ 수출"이라도 한국 통계와 상대국 통계가 다를 수 있다는 것을 독자는 모른다.
  • 양쪽 숫자를 맞대어 보려면 UN Comtrade에서 두 번 내려받고, 방향을 뒤집어 맞추고, 같은 조건(합계 행, 세관 절차 등)으로 걸러야 한다.
  • 차이가 보여도 "왜 다른지"에 대한 설명이 흩어져 있어서, 쉽게 "누가 속였다"는 결론으로 건너뛴다.

해결 방법

양쪽 신고값을 미리 받아 맞춰 둔다. 사용자는 두 나라를 고르면 두 막대(A가 신고한 수출, B가 신고한 수입)와 그 차이를 본다. 차이가 큰 품목과 해를 찾아 주고, 옆에 알려진 설명 후보(평가 기준, 경유지, 신고 시점, 비공개 처리 등)를 규칙에 따라 표시한다. 원인을 고르지는 않는다.

차별점 한 문장
"이 숫자를 믿어도 되나?"라는 질문을 화면 한가운데 두고, 통계의 기록 방식을 사용자가 직접 확인하게 만든다. 한쪽 숫자만 쓰는 뉴스로는 알 수 없는 정보다.

OECD의 균형 교역 통계(BIMTS)나 CEPII BACI처럼 양쪽 값을 "맞춘" 자료는 있다. 이 서비스는 맞추기 전의 차이 자체를 보여 주고, 맞춘 값(BACI)은 비교선으로 함께 놓는다. 시작 전에 비슷한 공개 도구를 한 번 더 조사해 방법 페이지에 적는다.

03다루는 질문

주 질문

같은 교역을 두 나라가 각자 신고한 값은 얼마나 다르고, 그 차이는 어느 쌍·품목·시기에 몰려 있나?

부 질문

  1. 한국의 수출 신고값과 상대국의 수입 신고값은 상대국마다 얼마나 다른가? 차이가 유난히 큰 상대국은 어디인가?
  2. 차이는 해마다 커지고 있나, 줄고 있나? 특정 해에 갑자기 바뀌었나?
  3. 차이가 큰 쌍에서, 차이는 어느 품목(HS 장)에 몰려 있나?
  4. 관세 같은 정책 발표 뒤에, 제3국을 거치는 경로의 차이가 커졌나? (3단계, Policyline과 연결. 같은 시기의 변화로만 보여 줌)

이 서비스가 답하지 않는 질문

  • "이 차이는 탈세·가격 조작·우회 수출 때문이다" 같은 원인 판정
  • 특정 기업·개인·선박에 대한 것
  • 어느 나라 통계가 "맞다"는 판정

06핵심 개념 쉽게 풀기: 숫자가 왜 다를까

거울 통계

A의 B 수출과 B의 A 수입은 같은 물건의 흐름을 양쪽에서 본 것이다. 둘을 짝지은 것을 거울 통계(mirror statistics)라고 하고, 둘의 차이를 비대칭(asymmetry)이라고 한다.

차이가 생기는 알려진 이유

이유쉬운 설명차이 방향
평가 기준 (CIF / FOB)국제 권고에 따라 대부분 나라는 수입을 운임·보험료를 포함한 값(CIF)으로, 수출을 배에 싣는 순간의 값(FOB)으로 기록한다. 그래서 같은 물건도 수입 쪽 숫자가 보통 조금 더 크다.수입 > 수출 쪽으로
상대국을 정하는 기준수입국은 보통 원산지를 상대국으로 적고, 수출국은 알고 있는 마지막 목적지를 적는다. 한국 물건이 홍콩을 거쳐 미국에 가면, 한국은 "홍콩 수출"로, 미국은 "한국산 수입"으로 적을 수 있다.쌍마다 다름. 경유 거점이 끼면 커짐
재수출·중계 무역경유지에서 다시 수출되는 물건이 어느 나라 통계에 어떻게 잡히는지가 나라마다 다르다.경유 거점이 낀 쌍에서 큼
신고 시점12월 말에 배에 실은 물건은 수출국에선 올해, 수입국에선 내년 통계에 잡힌다.해마다 앞뒤로 흔들림
비공개 처리나라마다 일부 품목·상대국을 비밀로 묶어 "기타"로 신고한다.한쪽만 작아짐
환율 환산각국 통화로 기록한 값을 달러로 바꿀 때 쓰는 환율과 시점이 다르다.작고 불규칙
품목 분류 차이같은 물건을 양쪽이 다른 HS 코드로 분류할 수 있다.품목별로는 크고, 합계로는 작음
신고 누락·오류·가격 조작가능성은 있지만, 이 화면의 자료만으로는 판단할 수 없다.알 수 없음
한 문장 요약
차이가 있다는 것은 "누가 틀렸다"가 아니라 "두 나라가 다른 규칙으로 같은 흐름을 적었다"일 때가 많다. 이 서비스는 그 규칙을 보여 주는 도구다.

설명 페이지: "물건 하나 따라가기" (가상)

개념 페이지에는 가상의 화물 하나가 A국 공장 → 배 → 경유지 → B국 항구로 가는 과정을 단계별로 보여 주고, 단계마다 A국 세관과 B국 세관이 무엇을 얼마로 적는지 나란히 표시한다. 모든 숫자에 "가상" 표시를 붙인다.

07데이터

① UN Comtrade (주 자료)

항목내용
무엇각국 세관이 신고한 상품 교역. 신고국(reporter) × 상대국(partner) × 품목 × 흐름(수출/수입) × 기간
주소comtradeplus.un.org · API comtradeapi.un.org
쓰는 범위연별(A) · HS 분류 · 상품 전체 합계(TOTAL), 2단계부터 HS 2단위(장)
쓰는 값primaryValue (미국 달러). 신고국이 정한 평가 기준(보통 수입 CIF, 수출 FOB)을 그대로 따른다
거르는 조건Policyline과 같게: 두 번째 상대국 없음(partner2Code = 0), 세관 절차 전체(customsCode = C00), 운송 수단 전체(motCode = 0)인 합계 행만
접근 방법키 없는 공개 미리보기는 한 번에 최대 500건, 기간 1개. 무료 개인 키는 하루 호출 수 한도가 있다(공식 안내 기준 하루 500회). 정확한 한도는 시작하는 날 개발자 포털에서 확인하고 README에 적는다
키 보관COMTRADE_KEY는 .env와 GitHub Actions 비밀값에만. 화면 코드에는 넣지 않는다 (화면은 미리 만든 JSON만 읽음)
늦게 나오는 정도나라마다 다르다. 신고하지 않은 해는 "신고 없음"으로 표시
이용 조건시작 전에 Comtrade 이용 약관을 확인해 출처 문구와 재배포 범위를 정한다. 원자료 전체는 저장소에 올리지 않는다

② CEPII BACI (비교선)

항목내용
무엇Comtrade의 양쪽 신고값을 바탕으로 수입값의 CIF 부분을 추정해 빼고, 신고국 신뢰도로 가중해 한 거래에 숫자 하나로 맞춘 자료
판HS92 (1995년부터 시계열). 쓴 판 번호를 화면에 표시
라이선스Etalab Open Licence 2.0 (출처 표시)
쓰는 곳쌍 화면에서 세 번째 표시(맞춘 값)로. "두 신고값 사이 어디쯤에 맞춰졌나"를 보여 준다

③ 1단계에서 다룰 나라 묶음

  • 한국 + 한국의 상위 교역국(BACI 최신 연도 기준 상위 15개 안팎) + 주요 경유 거점
  • 목록과 고른 기준은 data/meta.json에 적는다. 나라 수를 늘리는 것은 API 한도를 확인한 뒤.

④ 나라 코드

  • Comtrade 숫자 코드 → ISO3 문자 코드로 바꿔 쓴다. Comtrade의 "Other Asia, nes"(490)는 Tradeweave와 같은 규칙으로 대만으로 표시하고 방법 페이지에 적는다.
  • "Areas, nes"(지역 미상) 같은 묶음 상대국은 쌍 목록에서 빼되, 비공개 처리 신호를 계산할 때 쓴다.

08계산 방법

방향 하나(A → B)를 기준으로 정의한다. 반대 방향(B → A)도 같은 방식으로 따로 계산한다.

X = A가 신고한 B로의 수출 (FOB가 보통) M = B가 신고한 A로부터의 수입 (CIF가 보통)

차이

차이 = M − X (미국 달러)

차이율 (기본 지표)

차이율 = (M − X) ÷ ((M + X) ÷ 2) × 100 (%)

두 값의 평균으로 나누기 때문에 어느 쪽을 기준으로 해도 크기가 같고, −200%에서 +200% 사이에 들어온다. 양수면 "수입 쪽이 더 큼", 음수면 "수출 쪽이 더 큼".

배수 (보조 지표)

배수 = M ÷ X ("수입 신고가 수출 신고의 몇 배")

BACI와의 위치

위치 = (BACI − X) ÷ (M − X) (0이면 수출 쪽, 1이면 수입 쪽에 맞춰짐)

M과 X가 거의 같으면 위치는 의미가 없으므로 표시하지 않는다. BACI는 수입값에서 CIF 부분을 뺀 값이라 X(FOB)와 같은 기준에 가깝다.

품목 분해 (2단계)

HS 2단위(장)마다 같은 계산을 하고, 쌍 전체 차이에서 각 장이 차지하는 몫을 막대로 보여 준다. 합계 차이와 장별 차이의 합은 비공개 처리·분류 차이 때문에 맞지 않을 수 있고, 그 나머지를 "장에 나눌 수 없는 차이"로 따로 보여 준다.

빠진 값

  • 한쪽이 신고하지 않은 해: 차이를 계산하지 않고 "B 신고 없음"으로 표시. 0으로 보지 않는다.
  • 양쪽 값이 아주 작은 쌍(기준값은 meta.json): 차이율이 크게 튀므로 순위에서 기본으로 숨긴다.

09설명 후보 표시 규칙

차이가 큰 쌍·해·품목에는 "가능한 설명 후보"를 붙인다. 규칙은 미리 정하고 방법 페이지에 그대로 공개한다. 후보는 원인 판정이 아니다. 여러 개가 동시에 붙을 수 있고, 하나도 붙지 않을 수 있다.

후보붙이는 조건 (자료로 확인 가능한 것만)
평가 기준 (CIF/FOB)수입 쪽이 더 크고 차이율이 작은 범위일 때. 범위 기준은 BACI 문서 등 출처를 찾아 정하고, 출처를 찾기 전에는 이 후보를 늘 "기본 설명"으로만 보여 준다
경유 거점쌍의 한쪽이 data/hubs.json에 있는 나라일 때. 거점 목록은 통계기관·논문 설명을 출처로 붙여 정한다 (예: 재수출 비중이 큰 곳)
원산지 / 목적지 기준차이율이 크고, 같은 해 B가 다른 거점에서 신고한 "A 원산지" 수입이 있을 때 (2단계 이후 자료가 있으면)
신고 시점차이율 부호가 해마다 번갈아 바뀔 때
비공개 처리신고국의 "Areas, nes" 등 지역 미상 상대국 값이 그해 전체의 일정 비율을 넘을 때
품목 분류장별 차이는 큰데 합계 차이는 작을 때 (2단계)
신고 없음 / 개정한쪽이 신고하지 않았거나, 이전에 받은 값과 새로 받은 값이 다를 때

"가격 조작", "탈세", "우회 수출"은 후보로도 자동 표시하지 않는다. 방법 페이지에서 "이런 가능성도 연구에서 다뤄지지만, 이 자료만으로는 판단할 수 없다"고 한 번 설명한다.

11사실 · 해석 · 불확실 카드

사실두 신고값, 차이, 차이율, 연도 변화. 자동으로 만든다. 출처·받은 날짜 표시.
해석통계기관·논문이 이 쌍의 차이에 대해 설명한 것. 사람이 검수해 넣는다. 출처 링크 필수.
불확실자료만으로 알 수 없는 것. 공통 목록 + 쌍별 추가.

사실 카드 문장 틀 (자동)

{연도}에 {A}가 신고한 {B}로의 수출은 {X}, {B}가 신고한 {A}로부터의 수입은 {M}이다.
수입 쪽이 {차이} ({차이율}%) 더 {크다/작다}. {처음 연도}에는 차이율이 {값}%였다.
출처: UN Comtrade ({A} 신고, {B} 신고, {받은 날짜} 조회), CEPII BACI HS92 {판}.

해석 카드

  • 처음에는 예시 쌍 3개 안팎만 검수된 해석을 넣는다. 나머지는 "이 쌍에는 아직 검수된 해석이 없습니다".
  • data/interpretations.json: 쌍마다 {요약, 출처 제목, 링크, 확인 날짜}.
  • AI가 해석을 지어내지 않는다.

불확실 카드 공통 목록

  • 차이가 어느 이유로 얼마만큼 생겼는지는 이 자료로 나눌 수 없다.
  • 두 나라의 신고값 모두 나중에 고쳐질 수 있다.
  • 어느 쪽 숫자가 "맞는지"는 판단하지 않는다. 쓰임에 따라 고르는 것이다(예: 한국 수출 실적을 말할 때는 한국 신고값).
  • 신고 누락·오류·가격 조작 가능성은 이 화면으로 판단할 수 없다.

12문구 규칙

쓰는 말쓰지 않는 말
두 신고값이 다르다 · 어긋난다 · 차이가 있다틀렸다 · 거짓 신고 · 조작
설명 후보 · 알려진 이유 중 하나원인은 · ~때문이다 · 밝혀졌다
경유 거점이 낀 쌍우회 수출 · 원산지 세탁 · 밀수
같은 시기에 차이가 커졌다관세를 피하려고 · 제재를 피해

화면 문구를 다 만든 뒤 쓰지 않는 말 목록으로 검색해서 하나도 없는지 확인한다(설명 페이지에서 "판단할 수 없다"고 말하는 문장은 예외로 표시해 둔다).

13기술 구조와 파일

방식

  • 빌드 없는 정적 사이트: index.html 하나 + 바닐라 자바스크립트 + SVG 그래프. Vercel에 그대로 배포.
  • 데이터는 미리 받아 계산: 파이썬 스크립트가 Comtrade API로 받고(원자료는 내 컴퓨터에만), 화면용 JSON을 만든다. Policyline의 fetch_trade.py에 있는 Comtrade 호출·재시도·거르는 조건을 참고하되, 코드는 이 폴더 안에 따로 둔다(서비스 폴더끼리 서로 고치지 않는 규칙).
  • 화면은 서버 함수·데이터베이스·로그인·API 키가 필요 없다. 키는 데이터 받는 스크립트에만.
  • (선택) Policyline처럼 GitHub Actions로 달마다 다시 받아, 바뀌면 커밋 → Vercel 자동 배포.

15하지 않을 것

  • 차이의 원인 판정, 어느 나라 통계가 맞는지 판정
  • "우회 수출 의심 국가" 같은 목록이나 점수
  • 기업·개인·선박 단위 자료
  • HS 6단위 세부 품목 (1·2단계에서는 하지 않음. 자료 양과 비공개 처리 문제가 큼)
  • API 키를 화면 코드나 저장소에 넣는 것
  • 로그인, 회원가입, 개인정보 수집, 방문자 추적
  • 출처 없는 숫자, 가상 표시 없는 예시 숫자

16위험과 대응

위험대응
사용자가 차이를 "부정"의 증거로 읽음"숫자가 왜 다를까"를 메뉴 두 번째에, 쌍 화면에 설명 후보와 불확실 카드 고정
특정 나라를 겨냥하는 것처럼 보임순위 화면 기본 정렬을 교역 규모로, 문구 규칙 검사, 중립적 나라 표기
Comtrade 호출 한도·응답 오류원자료 캐시, 재시도·대기, 받은 범위를 meta.json에 기록
거르는 조건 실수로 같은 값을 두 번 더함합계 행만 쓰는 조건을 코드 한곳에 두고, 예시 쌍을 Comtrade 웹 화면 값과 대조
신고값 개정받은 날짜 표시, 다시 받을 때 바뀐 값을 "개정" 후보로 표시
경유 거점 목록이 자의적으로 보임항목마다 출처, 방법 페이지에 고른 기준 공개

17검수 기준

  • 예시 쌍 3개, 무작위 쌍 7개에서 X·M이 Comtrade 웹 화면에서 직접 찾은 값과 같다
  • 차이율 계산을 손으로 다시 해서 같다 (양수/음수 방향 포함)
  • 신고 없는 해가 0이 아니라 빈칸으로 보인다
  • 화면의 모든 숫자 옆에 출처와 기준연도(받은 날짜)가 있다
  • 쓰지 않는 말 목록 검색 결과가 0개다 (예외 문장 제외)
  • 설명 후보 칩을 누르면 붙은 규칙이 그대로 보인다
  • "숫자가 왜 다를까" 페이지의 모든 숫자에 "가상" 표시가 있다
  • API 키가 저장소·화면 코드 어디에도 없다 (검색으로 확인)
  • 휴대폰 375px에서 가로 스크롤 없음, 한/EN·다크/라이트 정상
  • CSV가 화면과 같은 값, 같은 출처 줄을 가진다

검수 결과는 mirror-gap/review/에 날짜별로 남긴다.

18지원서에서 말할 거리

  • 데이터를 믿기 전에 묻기: 정책 분석에 흔히 쓰는 교역 통계가 기록 방식에 따라 어떻게 달라지는지 직접 보여 줬다.
  • 규칙을 공개한 설계: 차이에 붙이는 설명 후보를 규칙으로 정하고 공개해, 판단과 사실을 분리했다.
  • 정책 연결: 관세·원산지 규정·경유 무역 같은 통상 정책 주제와 통계 품질 문제가 만나는 지점을 다뤘다.
  • 재현 가능성: 받은 날짜, 거르는 조건, 계산식, 다시 받는 절차를 모두 공개했다.
