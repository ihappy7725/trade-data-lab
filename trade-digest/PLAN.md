# Trade Digest 한 장 기획서

작성일: 2026-11-16 · 작성자: 정주연 · 상태: 기능 범위 확정, 1단계 구현 준비

## 이름
- 서비스 이름: **Trade Digest** (2026-11-16 확정. 기획서의 임시 이름은 Report Plain)
- 같은 프로젝트의 Trade News Room(뉴스)과 헷갈리지 않게 이름 옆에 부르는 말을 함께 쓴다
- 부르는 말: "보고서 쉬운 말 요약"

## 한 줄 소개
Trade Digest는 국제기구·KITA·KOTRA 보고서의 **핵심 주장 / 근거 데이터 / 한계**를 한 장으로 정리하고, 요약 문장마다 원문 쪽수를 붙여 바로 확인할 수 있게 하는 웹서비스다.

## 누가 쓰나
- 중심: 국제통상·국제정책을 공부하며 과제·글·스터디(KITA 보고서 스터디 등)에서 보고서를 근거로 써야 하는 사람
- 보조: 담당 시장 전망 보고서를 빨리 읽어야 하는 해외영업 신입

## 불편
- 보고서가 길고(수십~200쪽) 영어이며, 핵심 주장과 근거, 한계가 한곳에 정리돼 있지 않다.
- 일반 AI 요약은 빠르지만, 그 문장이 원문 어디에 있는지 확인하기 어렵고 틀린 쪽수를 대기도 한다.

## 해결 방법: 두 가지 입구, 같은 요약 화면
| | ① 보고서 서가 | ② 내 PDF 바로 요약 |
|---|---|---|
| 무엇 | 내가 골라 둔 보고서 5~8개 | 이용자가 올린 PDF 1개 |
| 만드는 방법 | 미리 요약 → **내가 쪽수·문장을 직접 검수** → JSON 저장 | 그 자리에서 Claude API로 요약 (Vercel 서버 함수) |
| 화면 표시 | `검수 완료` 배지 | `자동 요약 · 사람이 검수하지 않음` 배지 |
| 저장 | JSON 파일 (요약만, PDF는 원문 링크) | **저장하지 않음** (파일·요약 모두 서버에 남기지 않음) |

핵심 아이디어: **둘은 같은 요약 과정을 쓴다.** 서가는 그 결과를 사람이 한 번 더 검수한 것이고, 바로 요약은 검수 전 결과다.
이 차이를 화면에 그대로 드러내는 것이 "사실과 해석을 나눈다"는 프로젝트 원칙과 이어진다.

## 핵심 기능 3개
1. **한 장 요약 (주장 / 근거 / 한계)**: 칸마다 2~4문장. 근거 칸의 숫자는 보고서에 적힌 값 그대로, 단위·기준연도와 함께.
2. **문장마다 원문 쪽수 + 쪽수 확인 표시**: 요약 문장마다 원문 쪽수와 짧은 근거 구절을 붙인다. 프로그램이 그 구절이 실제로 그 쪽에 있는지 대조해서
   `쪽수 확인됨` / `확인 못 함`을 표시한다. (일반 AI 요약 도구와 가장 크게 다른 점)
3. **쉬운 말 용어 풀이 + 관련 서비스 연결**: 어려운 용어(예: 상계관세, 교역조건)를 한 줄로 풀고, 보고서 숫자와 관련된 나라·품목이면
   Tradeweave·Policyline 화면으로 이어 준다 → "보고서 숫자를 데이터로 직접 확인".

## 더 넣을 기능 (자세한 내용: [IDEAS.md](IDEAS.md))
- 한 가지 더: **A. 보고서 숫자 → 데이터로 확인**, **B. 같은 질문, 다른 기관**, **C. 한계 점검표**
- 부가 탭: **정책 용어 사전**, **보고서 달력**

## 한 페이지 구조
- 상단 메뉴: `보고서 서가` (기본) · `용어 사전` · `보고서 달력`
- 서가 화면
  - 위: 보고서 서가 카드 (기관, 제목, 발행일, 쪽수, 한 줄 요지, `검수 완료` 배지)
  - 아래: "내 PDF로 해 보기" 상자 하나 (보조 입구)
- 보고서 상세 화면
  - 한 장 요약 (주장 / 근거 / 한계, 문장마다 쪽수)
  - 근거 숫자 옆 `데이터로 직접 보기` (A)
  - `한계 점검표` (C)
  - `다른 기관은?` (B, 같은 질문을 다룬 보고서가 있을 때만)
- 첫 화면에서 할 단 하나의 행동: **보고서 카드 하나 고르기**

## 만드는 순서
| 단계 | 만들 것 | 목표 |
|---|---|---|
| 1 | 핵심 3기능 + 서가 보고서 1~2개 + A | **오늘 목표** |
| 2 | C 한계 점검표 (서가 보고서) | 오늘 가능하면 |
| 3 | 정책 용어 사전 (20개 안팎) | 다음 |
| 4 | B 같은 질문 다른 기관, 보고서 달력 | 그다음 |
- 화면 틀(상단 메뉴, 상세 화면 자리)은 1단계에서 미리 만들고, 아직 없는 기능은 메뉴에 `준비 중`으로 둔다.

## 바로 요약(②) 동작 방식
1. 브라우저에서 PDF 글자를 쪽별로 뽑는다 (pdf.js). 파일 자체는 서버로 보내지 않는다.
2. 쪽 번호가 붙은 글자만 서버 함수로 보낸다 → Claude API가 정해진 형식(JSON)으로 주장/근거/한계 + 쪽수 + 근거 구절을 돌려준다.
3. 브라우저에서 근거 구절이 그 쪽 글자에 있는지 대조해 확인 표시를 붙인다.
4. 제한: 쪽수 상한(예: 80쪽, 정할 것), 스캔본(글자 없는 PDF)은 "지원하지 않음" 안내.
- API 키는 `.env` / Vercel 환경 변수에만. 서버는 받은 글자와 요약을 저장·기록하지 않는다.
- 쓸 Claude 모델과 하루 사용 상한(비용 보호)은 구현 단계에서 정한다.

## 서가(①) 만드는 방식
- `scripts/`에서 ②와 같은 요약 지시문으로 초안을 만든다 → 원문을 보며 문장·쪽수·숫자를 직접 고친다 → `data/reports.json`에 `reviewed: true`와 검수일 저장.
- 200쪽짜리는 전체가 아니라 요약(Executive Summary)과 핵심 장 1~2개만 다루고, 다룬 범위를 화면에 적는다.
- PDF는 서가에 올리지 않고 기관 원문 링크만 건다. 요약은 내 말로 쓰고, 원문 인용은 짧게만.
- 보고서마다 이용 조건(라이선스, "무단전재 금지" 여부)을 확인해 기록한다.

## 하지 않을 것
- 보고서에 없는 숫자를 만들거나 보고서 숫자를 고치지 않는다.
- 보고서 주장을 사실처럼 단정하지 않는다. "보고서는 ~라고 본다"로 쓴다.
- 올린 PDF와 요약을 저장하지 않는다. 회원가입·개인정보 수집 없음.
- 원문 PDF를 다시 배포하지 않는다.
