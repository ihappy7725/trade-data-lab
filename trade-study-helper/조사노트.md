## 1) RAG 챗봇 부품 — import 한 줄씩

| 부품 | import 한 줄 | 상태 | 근거 |

| 문서 불러오기 | `from langchain_community.document_loaders import TextLoader` | **[확인 필요]** | DeepWiki는 TextLoader/PyPDFLoader 정의를 답변 근거에서 찾지 못했다고 함. 소스에서 `langchain_classic/document_loaders/text.py`(구버전 패키지)는 확인했지만 현행 `langchain-ai/langchain-community` 저장소는 GitHub API 호출 한도 때문에 확인하지 못함 |
| 자르기 | `from langchain_text_splitters import RecursiveCharacterTextSplitter` | **[확인]** | `libs/text-splitters/langchain_text_splitters/__init__.py` 에서 export 확인 |
| OpenAI 임베딩 | `from langchain_openai import OpenAIEmbeddings` | **[확인]** | `libs/partners/openai/langchain_openai/__init__.py` 에서 export 확인 |
| 벡터 저장소 | `from langchain_core.vectorstores import InMemoryVectorStore` | **[확인]** | `libs/core/langchain_core/vectorstores/__init__.py` 에서 export, 정의는 `in_memory.py` |

**근거 문서(DeepWiki가 언급한 위키 페이지)**: "Retrieval Primitives: Documents, Vector Stores, Indexing", "OpenAI Integration", "Vector Stores and Retrieval Partners"

## 2) LangGraph 가장 짧은 예: StateGraph · 노드 · 엣지 · START/END

```python
from typing_extensions import TypedDict
from langgraph.graph import END, START, StateGraph

class State(TypedDict):
    foo: str
    bar: str

def node(state: State):
    return {"bar": state["foo"] + "!"}

graph = StateGraph(State)
graph.add_node("node", node)
graph.add_edge(START, "node")
graph.add_edge("node", END)
graph = graph.compile()
print(graph.invoke({"foo": "hello"}))   # {'foo': 'hello', 'bar': 'hello!'}
```

- **[확인]** `StateGraph(...)`, `add_node`, `add_edge(START, ...)`, `add_edge(..., END)`, `compile()` 호출 순서는 `libs/langgraph/tests/test_pregel.py` 의 그래프 빌드 코드(약 3463–3476줄)에서 같은 패턴으로 확인했습니다. 단, 그 테스트의 상태는 `my_key` 하나이고, 위 예시의 `foo`/`bar` 형태는 같은 파일의 다른 테스트(약 4338줄 `return {"bar": state["foo"] + "!"}`)에서 확인했습니다. 두 줄을 합친 전체 코드를 실행해 본 것은 아닙니다.
- **[DeepWiki]** 근거 문서: "StateGraph API"(위키), `libs/langgraph/langgraph/graph/state.py`
- **[확인 필요]** `from langgraph.graph import END, START, StateGraph` 한 줄이 현재 버전에서 그대로 동작하는지는 실행해 보지 않았습니다.

## 3) ChatOpenAI로 OpenAI 모델 부르기 (모델 이름은 .env에서)

```python
import os
from dotenv import load_dotenv            # pip install python-dotenv
from langchain_openai import ChatOpenAI

load_dotenv()                              # .env 파일을 읽어 환경 변수로 올림
model = ChatOpenAI(model=os.environ["OPENAI_MODEL"])
response = model.invoke("안녕하세요!")
print(response.content)
```

- **[확인]** `from langchain_openai import ChatOpenAI` 는 `libs/partners/openai/langchain_openai/__init__.py` 에서 export 확인
- **[DeepWiki]** `ChatOpenAI(model=...)`, `.invoke(...)` 사용법 — 근거 파일 `libs/partners/openai/langchain_openai/chat_models/base.py` (DeepWiki가 가리킨 파일, 이 파일의 docstring은 직접 열어 확인하지 않음)
- **`load_dotenv` 는 LangChain이 아니라 `python-dotenv` 패키지**입니다. DeepWiki 답변에 나왔지만 저장소 근거는 없습니다.
- 모델 이름은 코드에 직접 쓰지 않고 `OPENAI_MODEL` 환경 변수에서 읽습니다. (프로젝트 CLAUDE.md의 규칙과 같습니다.) API 키 값은 이 노트에 적지 않았습니다.
- **[확인 필요]** 현재 버전에서 `model=` 인자 이름이 그대로인지, 응답 형식(`response.content`)이 맞는지는 실행해 보지 않았습니다.
